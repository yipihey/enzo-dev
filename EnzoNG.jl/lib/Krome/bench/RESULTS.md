Generated by `bench/compare_krome_enzo.jl` (Julia 1.12, CPU). KROME's
`react_primordial` and Enzo's `calc_rates.F` are both Abel+97-based, so this is a
cross-implementation check: KROME parsed/compiled by Krome.jl vs Enzo's tables.

`react_primordial`: 12 species, 38 reactions — **all 38 tabulated** (0 density-dependent, 0 skipped).

## Performance (CPU, per cell, one macro-step)

| cells | Enzo-port `solve_rate_cool!` (9-sp, specialized) | KROME `generic_step!` (12-sp, generic) |
|------:|:-------------------------------------------------|:----------------------------------------|
| 10⁴ | 0.17 µs/cell | 222 µs/cell |
| 10⁵ | 0.14 µs/cell | 209 µs/cell |

The specialized Enzo-port solver is ~1300× faster than the generic executor —
the expected cost of generality (the generic loop evaluates all 38 reactions ×
species each sub-step, and is the CPU scalar path, not the tabulated KA-GPU one).

**Takeaway.** KROME and Enzo agree on primordial chemistry to ≤1% (exact on
recombination). Use the specialized `solve_rate_cool!` for the primordial network
in production; use the KROME path for *flexibility* — arbitrary networks (CO,
metal, dust) that Enzo's hand-written solver doesn't cover — accepting the
generic-executor cost (and optimize / move it to the GPU tabulated path where the
network is temperature-only).
